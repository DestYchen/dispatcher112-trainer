## Исправления при приёмке

Истёкший ORM-объект больше не ломает WebSocket после rollback. Кэшированный вход сохраняет рабочее место при временном сбое; отказ доступа обрабатывается отдельно. Старый сокет и запоздавший ответ не закрывают новое соединение. Очередь HTTP повторяется по heartbeat даже без события online; исходные ключи повторов сохраняются. Отключившийся получатель не задерживает общую очередь.

Массовая выдача публикуется одной Redis pipeline; сводка читается без блокировки занятия и рассчитывается одним процессом. Согласованы сроки повторного использования соединений шлюза/backend. Большие группы используют постоянные пулы в пределах общего бюджета БД.

XLSX сохраняет семь канонических колонок, числовые типы и отметку ручной оценки; текст не становится формулой. MP3 формируется локально, исходный WAV сохраняется. Все решения — [docs/DECISIONS.md](docs/DECISIONS.md).

## Ограничения и невыполненные критерии PLAN.md

1. Этап 7: нет оригинальных PDF-билетов; учебные примеры не объявляются оригиналами заказчика.
2. Этап 16: результаты относятся к доступному Windows/Docker-стенду (i5-12450H, 15,73 ГиБ RAM, Docker 7,62 ГиБ), пяти браузерным профилям и указанному профилю 100 HTTP/WebSocket-участников. Это не 100 физических АРМ. ТЗ требует сервер от 32 ГБ; проверка на целевом сервере, физических гарнитурах и разных компьютерах кластера не выполнена. Жёсткие синхронные прогоны с превышенными задержками сохранены в `full-tz-load-100*.json`; они не объявлены успешными.
3. Этап 17: чистая установка успешна. Предметная сверка требует оригинальных XLSX/CSV и PDF, которых нет среди трёх DOCX в «данные UI». Адрес и доступ внешней площадки для публикации не предоставлены.

История занятий сохраняется; проверочные учётные записи деактивируются только по аудиту их создания инструментом. Резервный VHDX переноса Docker не удаляется.
Заключительная проверка обычного запуска: один backend, 20×10 — p95 332,37 мс (порог 300 мс не пройден), 1400 событий без потерь. Для класса оставлены два backend, бюджет 70/87 соединений, обслуживание выключено; повторный замер прошёл: p95 164,46 мс, 1400 событий без потерь (full-tz-load-20-two.json). Однопроцессный результат сохранён в full-tz-load-20-final.json.
