# Хранилище Docker на этом компьютере

26.09.2026 хранилище Docker Desktop 4.41.2 (WSL2, Engine 28.1.1) перенесено с C: на D:. Выбран локальный раздел NTFS с достаточным свободным местом. C: и D: находятся на одном физическом SSD.

- Рабочий диск: `D:\DockerData\wsl\disk\docker_data.vhdx`.
- Настройка `CustomWslDistroDir` в `%APPDATA%\Docker\settings-store.json`: `D:\DockerData\wsl`.
- Копия диска до переноса: `D:\DockerData\migration-backup-20260926\docker_data.pre-move.vhdx` (около 41,65 ГиБ).
- Исходные настройки: `D:\DockerData\migration-backup-20260926\settings-store.before-move.json`; дополнительная копия — `%APPDATA%\Docker\settings-store.before-disk-move-20260926.json`.
- Docker Desktop, рабочая папка проекта, `.env`, сертификаты и подключённые папки проекта остались по прежним путям. Команды `make` не изменились.

Docker штатно остановлен перед копированием. До запуска копии сверены полные SHA-256 обоих файлов: `A007655AD61F2D41EFA69CB04B0908DADF1C3749B94C12BCF17652E548300D48`, размер 44 721 766 400 байт. После запуска на D: подтверждены все прежние 30 контейнеров, 12 образов, 103 тома и сети проектов. Изменился только идентификатор встроенной сети `bridge` при перезапуске движка. Лишь после проверки прежний неиспользуемый диск с C: перенесён в резервную папку на D:.

После переноса свободно около 45,5 ГиБ на C: вместо 3,9 ГиБ; на D: — около 82,8 ГиБ с учётом отдельной копии для отката. Эта копия на том же физическом SSD предназначена для отката переноса, а не для защиты от поломки накопителя. Она отражает состояние до переноса, последующие изменения в неё не попадают. Рабочий файл в `wsl\disk` удалять нельзя.

При проверке обнаружено существовавшее до переноса повреждение Redis: файл `appendonly.aof.2.incr.aof` содержал корректный префикс 13 955 442 байта и хвост из 537 нулевых байт. Исходный каталог сохранён в `D:\DockerData\migration-backup-20260926\redis-original`. На остановленном Redis штатная `redis-check-aof --fix` удалила только нулевой хвост; повторная проверка всех файлов AOF прошла. Копия VHD до переноса содержит исходное повреждение Redis.

Итог: все прежние 26 запущенных сервисов работают, все настроенные healthcheck проходят; проверены страницы, `/healthz`, вход с CSRF и получение пользователя ADMIN по HTTPS для основной установки `https://localhost:5173` и проверочной восстановленной установки `https://localhost:15173`. Сертификаты проверены локальным CA. Контроллер с Docker socket не включался, тома и образы не очищались.

Локальные результаты проверок: `artifacts/docker-storage-move-20260926/` (`before.json`, `hash-check.json`, `inventory-check.json`, `archive-result.json`, `final-check.json`). Это обслуживание окружения; оно не завершает этапы 15–17 разработки. Код приложения не менялся, `make check` для переноса не запускался.
