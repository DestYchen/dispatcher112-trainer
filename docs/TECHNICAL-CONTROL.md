# Технический пульт

Штатный режим — `TECHNICAL_CONTROL_MODE=local`: постоянный монитор читает состояние, нагрузку и журналы 13 сервисов. Администратор формирует подписанный запрос; оператор сервера выполняет его локальной командой. Обслуживание, роли, фиксированный перечень сервисов, однократное исполнение и аудит проверяются сервером и исполнителем. Постоянного Docker socket у приложения нет. Команды и принятые операции — [LOCAL-OPERATIONS.md](LOCAL-OPERATIONS.md).

Создание копий, восстановительная проверка и расписание выполняются отдельным сервисом backup по подписанным файловым заданиям. SQL-роль `dispatcher_backup` читает рабочие таблицы и создаёт собственные проверочные БД без SUPERUSER/CREATEROLE. Для полного снимка исполнитель читает частную конфигурацию и остаётся доверенным процессом. Границы — [DEPLOY.md](DEPLOY.md).

Технический отчёт показывает статистику, ошибки HTTP/операций/генерации/SIP, JSON периода, проверки схемы, ссылочной целостности и защиты аудита. Проверка рабочих файлов сравнивает их с выбранной полной копией. Состав измерений — [DIAGNOSTICS.md](DIAGNOSTICS.md) и [FILE-INTEGRITY.md](FILE-INTEGRITY.md).

В исходниках сохранён отдельный профиль `technical-control` с Docker socket и HTTPS/API-токеном. Он исключён из обычного запуска и не нужен для реализованного локального обслуживания. Его запуск был отклонён автоматической проверкой разрешений 26.09.2026; он не запускался, фактическая интеграция этого дополнительного профиля не заявляется. Исполнение через локальную команду проверено отдельно и завершает необходимый сценарий управления сервисами.

Этап 15 принят с локальным исполнителем, TLS, обновлениями, резервированием, восстановлением и возвратом. Результаты и ограничения — [PROGRESS.md](../PROGRESS.md).
