# Параметры системы

Администратор открывает «Параметры системы». Раздел показывает сохранённую редакцию и свежие подтверждения сервера приложения, обработчика заданий и телефонии. При первом открытии используются исходные значения. Если процесс отсутствует или связь потеряна, применение не считается подтверждённым.

1. Завершите занятия, генерацию сценариев и SIP-вызовы.
2. В «Управление сервисами» включите обслуживание с указанием причины.
3. В «Параметры системы» измените значения и укажите причину изменения (5–1000 символов).
4. Сохраните параметры и дождитесь подтверждения всех рабочих процессов. Ошибка применения требует проверки технического отчёта и повторного обновления состояния; обслуживание остаётся включённым.
5. Снимите обслуживание в «Управление сервисами».

Сохранение создаёт новую редакцию в `system_settings.runtime_configuration` и неизменяемое событие `RUNTIME_CONFIGURATION_CHANGED` с автором, причиной, предыдущими и новыми значениями. Потерянный ответ можно повторить с тем же идентификатором запроса. Изменение другим администратором требует явной загрузки текущей редакции; фоновое обновление состояния не стирает черновик.

| Параметр | Исходное значение | Диапазон |
| --- | --- | --- |
| Пул сервера приложения | 20 | 5–50 |
| Пул обработчика заданий | 5 | 1–20 |
| Пул телефонии | 5 | 1–10 |
| Дополнительные соединения каждого процесса | 5 | 0–10 |
| Ожидание свободного соединения | 10 с | 1–60 с |
| Тайм-аут SQL-запроса | 30 000 мс | 500–30 000 мс |
| Ожидание блокировки БД | 3 000 мс | 100–10 000 мс |
| Входящий звонок | 40 с | 5–120 с |
| Вызов без ответа | 60 с | 5–120 с |
| Предельная длительность вызова | 3 600 с | 60–3 600 с |
| Уровень журнала | INFO | INFO / WARNING / ERROR |
| Журнал HTTP-запросов | Включён | Включён / выключен |

Тайм-аут блокировки не превышает тайм-аут запроса. Длительность звонка ≤ ожидание ответа ≤ длительность вызова. Сервер проверяет сумму размеров трёх пулов и трёх резервов дополнительных соединений: она не должна превышать `max_connections - superuser_reserved_connections - 10`. Этот расчёт относится к текущей поставке с одним процессом каждого типа; учёт нескольких узлов должен быть расширен и проверен на этапе 16 до их запуска.

Каждый рабочий процесс проверяет редакцию раз в две секунды. Перед заменой пула он открывает соединение с PostgreSQL и проверяет фактические `statement_timeout` и `lock_timeout`. Уже открытые транзакции завершаются на прежних соединениях. При ошибке подключения прежний пул сохраняется, новое применение не подтверждается. Подтверждение содержит идентификатор процесса, редакцию, размер пула, число занятых соединений и тайм-ауты. Запись живёт 15 секунд; UI считает свежими только подтверждения моложе 10 секунд. При запуске после остановки процессы повторно читают сохранённую редакцию.

Уровень журналирования действует на консольные журналы трёх процессов. Неизменяемый аудит действий, учёт запросов в метриках и отдельные технические записи об ошибках продолжают работать. Выключение HTTP-журнала не выключает обработку запросов и аудит. Пароли, адрес БД, сертификаты, маршруты телефонии и параметры установки меняет оператор через конфигурацию развёртывания; эта форма не принимает секреты. Обязательные комментарии, адресная проверка, таймеры карточек и оценивание сохраняют правила занятия.

Если после сохранения параметров завершился только HTTP-запрос, это ещё не означает их применение. API запрещает снимать обслуживание при отсутствии свежего подтверждения хотя бы одного процесса текущей редакции. После перезапуска процесс получает новый идентификатор; прежнее подтверждение перестаёт учитываться через 10 секунд.
