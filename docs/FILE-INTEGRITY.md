# Проверка файлов системы

Результат доступен администратору в «Техническом отчёте» и «Резервных копиях». Проверяется содержимое текущих файлов относительно явно выбранной подписанной полной копии. Создание следующей резервной копии не заменяет эталон. Изменённый, пропавший или добавленный файл означает расхождение, а недоступность чтения — невозможность подтвердить результат.

## Выбор эталона

1. Завершите активное обучение и включите обслуживание с причиной.
2. Убедитесь, что установленная версия и настройки приняты, создайте полную копию.
3. Выполните проверку её восстановления. Старая копия без исходного кода не подходит.
4. В блоке «Выбор эталона» выберите проверенную копию, укажите причину и нажмите «Принять копию как эталон».
5. Дождитесь завершения операции. Сервис ещё раз сравнит текущие файлы с выбранной копией; при расхождениях новый эталон не принимается. Затем снимите обслуживание.

Автор, причина, выбранная копия, запрос и результат сохраняются в неизменяемом аудите технических операций. Повтор запроса с тем же id не выполняет операцию заново. Исправление файлов не производится: администратор получает сведения, а восстановление выполняет отдельной предусмотренной процедурой.

Выбранная копия закреплена. Очистка сохраняет последние N копий и дополнительно эталон, если он старше; при повреждении указателя очистка прекращается до удаления данных. После выбора другого эталона прежний снова подчиняется обычному сроку хранения. Базовая политика 14 копий остаётся неизменной.

## Что проверяется

- Исходники API/UI, миграции, статические ресурсы интерфейса, скрипты, документация и lock-файлы по каталогу `program_files`.
- `.env`, Compose, инфраструктурные файлы и секреты из каталогов, уже доступных сервису резервирования только для чтения. Ключ подписи копий отдельно не сравнивается с собственным хешем: он нужен для проверки подлинности эталонного описания.
- Постоянные каталоги данных `fonts`, `llm`, `tickets`, `voices` и исходные `classifier.xlsx`, `streets.csv`.

Состав и SHA-256 берутся из подписанного описания полной копии `dispatcher-backup-2`. Отдельный подписанный указатель хранится в `.backups/integrity-baseline.json`; он содержит только идентификаторы, причину и время выбора. Проверка не читает пути, заданные HTTP-клиентом. Символические ссылки, junction/reparse points, нештатные типы файлов и неполный обход каталогов не дают успешного результата. Содержимое файлов и хеши секретов в UI и результат не попадают.

Изменяемые учебные материалы и записи разговоров, содержимое БД, фактические файлы установленных зависимостей и работающие образы контейнеров в эту проверку **не входят**. Проверки БД/защиты аудита описаны в DIAGNOSTICS.md; полное восстановление копии проверяет все сохранённые данные. Подписанные пакеты и закрепление образов при установке описаны в UPDATES.md. Проверка данной группы файлов не означает подтверждения целостности всех компонентов работающей системы; оставшиеся пункты этапа 15 перечислены в PROGRESS.md.

## Состояния и сроки

Сервис резервирования выполняет проверку раз в пять минут. В обслуживании можно запустить её кнопкой «Проверить файлы сейчас». Работает существующий ограниченный исполнитель без Docker socket, дополнительных каталогов и внешней сети.

| Состояние | Значение |
| --- | --- |
| EMPTY | Эталон не выбран; положительный вывод не делается. |
| RUNNING | Начата новая проверка. |
| OK | Проверенные файлы совпадают с эталоном на указанное время. |
| FAIL | Обнаружены расхождения либо недействителен подписанный эталон. |
| UNAVAILABLE | Чтение недоступно, исполнитель не отвечает или результат устарел. |

Подтверждение работы исполнителя должно быть моложе 30 секунд. Завершённый результат действует не более 10 минут, RUNNING — не более трёх минут; даты из будущего не принимаются. Отсутствующий или недействительный подписанный результат возвращает 503. При потере связи UI сохраняет поля формы, но перестаёт показывать прежнее OK как подтверждённое.

Пределы проверки: 20 000 файлов и 64 ГиБ выбранных данных, до 120 секунд чтения. Результат содержит общий счётчик нарушений и не более 200 строк в пределах 128 КиБ; сокращённый список явно помечается. Превышение пределов не выдаётся за успех.

## API

`GET /api/v1/admin/diagnostics/files`: только ADMIN, `Cache-Control: private, no-store`; возвращает подписанный результат исполнителя, проверенный сервером, либо 503 `INTEGRITY_UNAVAILABLE`.

Существующий `POST /api/v1/admin/operations/jobs` (ADMIN, CSRF, обслуживание) принимает два дополнительных `kind` при `service: "backup"`:

- `backup_integrity_check`: `{id,kind,service}` — запустить проверку текущего эталона.
- `backup_integrity_baseline`: `{id,kind,service,snapshot,reason}` — выбрать полный проверенный снимок; reason 5–1000 символов. До сохранённой проверки восстановления — 409 `BASELINE_NOT_VERIFIED`.

Результат операции с `status: SUCCEEDED` означает, что проверка выполнена. Её вывод находится в `result.status`: он может быть FAIL. «Проверка выполнена» не означает «нарушений нет». Повтор и получение результата используют обычный протокол технических операций с неизменяемым аудитом.
