# Технический отчёт администратора

Раздел **«Технический отчёт»** доступен только ADMIN. Он работает через обычный API и не требует технического контроллера или Docker socket. Преподаватель и учащийся получают 403, в том числе при прямом запросе выгрузки.

## Состав отчёта

- **Использование за период:** число пользователей с действиями в аудите, начатых занятий, выданных/завершённых карточек, учебных звонков, заданий генерации и записей аудита. Это агрегаты без имён, ответов, оценок и содержимого карточек. «Пользователи с действиями» не означает число одновременно подключённых браузеров.
- **Текущее состояние:** число учётных записей, действующих пользователей/рабочих мест и идущих занятий. Эта часть относится к моменту формирования, а не к историческому периоду.
- **Работа API:** число запросов, ошибок 5xx, средняя длительность ответа и число ответов дольше двух секунд. Счётчики относятся только к текущему процессу API; дата начала показана явно. Перезапуск сбрасывает их. Это не измерение отклика интерфейса и не приёмка 100 пользователей.
- **Технические сбои:** сохранённые ошибки HTTP 5xx, неудачные технические операции, завершившиеся ошибкой задания генерации и SIP-вызовы. Для API видны код, HTTP-статус, метод, шаблон маршрута и номер запроса. Для остальных источников — категория и номер операции, без исходного текста ошибки или учебных данных.
- **Целостность БД и защита аудита:** проверки ниже. Их результат не подменяет проверку всех файлов программы или восстановление полного снимка.

По умолчанию используется последний день. Период задаётся с часовым поясом, от секунды до 366 дней; начало включается, окончание исключается. Пользователь вводит локальное время, браузер передаёт UTC. Пустой период показывает отсутствие зарегистрированных действий/сбоев, при этом текущее состояние остаётся доступным.

Показаны 50 сбоев на странице; порядок — время от новых к старым, затем источник и идентификатор. Переключение страниц сохраняет границы периода. **«Скачать полный отчёт JSON»** выгружает все страницы выбранного периода, а не только видимую страницу. При более чем 10 000 сбоях экспорт возвращает явную ошибку с предложением сократить период. Обрезанный файл не выдаётся за полный. Данные и выгрузка имеют Cache-Control: private, no-store. Просмотр и экспорт записываются в аудит.

## Постоянный журнал ошибок API

После запуска этой версии middleware сохраняет 5xx отдельной транзакцией в существующем неизменяемом `audit_log`, действие `SYSTEM_HTTP_ERROR`. Не сохраняются тело/параметры запроса, cookies, авторизационные заголовки, содержимое исключения или идентификатор пользователя. Маршрут берётся из шаблона роутера; произвольный URL становится `unmatched`, неизвестный HTTP-метод — `OTHER`. В системном журнале запросов также используется шаблон вместо фактического URL.

Запись ограничена 0,5 секунды и не маскирует исходную ошибку. При недоступной БД либо превышении срока сервер пишет сообщение без деталей исключения в штатный системный журнал и увеличивает счётчик ошибок сохранения. UI показывает предупреждение о неполноте постоянного журнала. Этот счётчик сбрасывается вместе с процессом, сохранённые записи аудита — нет. Прежние 5xx до установки этой версии задним числом не восстанавливаются. Ошибки 4xx остаются ожидаемыми отказами запросов; значимые события безопасности по-прежнему записываются собственными обработчиками аудита.

Журналы всех контейнеров и их загрузка остаются в пульте технического контроллера; этот отчёт не получает дополнительного доступа к файловой системе хоста.

## Проверки целостности

1. Версия `alembic_version` совпадает с вершинами миграций поставленной программы.
2. `audit_immutable` включён для UPDATE/DELETE каждой строки, не имеет условия пропуска, использует неизменённую функцию запрета изменения аудита.
3. `dispatcher_app` и `dispatcher_backup` не являются суперпользователями, не создают роли, не обходят RLS/репликацию, не наследуют явно выданные роли, не владеют рабочей БД или её объектами. У приложения запрещён CREATEDB, у backup он необходим для проверочных БД.
4. Проверяются опасные табличные и поколоночные права, права на последовательности, изменение аудита/версии схемы и создание объектов в public. У backup дополнительно запрещено изменение всех рабочих таблиц и использование последовательностей для записи.
5. Внешние ключи, описанные моделями программы, присутствуют в БД; все имеющиеся внешние ключи прошли валидацию. Удалённый либо NOT VALID ключ считается нарушением.
6. Каталог резервирования имеет правильную подпись, а описания перечисленных копий отмечены исполнителем как целые. Последняя сохранённая проверка восстановления показана отдельной датой. Пустой каталог отображается как «Нет копий для проверки», недоступность — «Не удалось проверить»; эти состояния не выдаются за повреждённую копию и не скрывают остальные результаты.

Эти проверки обнаруживают перечисленные изменения схемы/прав и проверяют подписанные сведения резервирования. Они не проверяют хеш каждого рабочего файла, аппаратный накопитель или подлинность самого проверяющего кода. Проверочное восстановление всех файлов и БД запускается отдельно в «Резервных копиях». Целостность всей поставки остаётся отдельной задачей этапа 15.

## Воспроизводимая проверка

- `make check`: периоды/часовые пояса, доступ, точные счётчики, пагинация/экспорт, отсутствие учебного содержимого, запись сбоев и реальные изменения схемы/ACL внутри откатываемых тестовых транзакций.
- `python scripts/check_diagnostics_ui.py`: явные API-фикстуры четырёх состояний, сохранение дат после ошибки, полный экспорт со второй страницы, нарушения целостности; 35 компоновок 360–1920 px.
- `python scripts/check_diagnostics_live.py`: свободный заполненный стенд с демонстрационным администратором. Скрипт включает обслуживание, получает настоящий 503 от выключенного контроллера, проверяет однократную запись, перезапускает только backend, проверяет сохранность ошибки и сброс текущих счётчиков, скачивает полный JSON и снимает обслуживание. Семь компоновок проверяются на реальном API. Если уже включено обслуживание или идёт занятие, проверка отказывается вмешиваться.

Результаты и актуальный остаток этапа — PROGRESS.md; артефакты — `artifacts/ui-review/diagnostics-*.json` и журналы рядом.
