# Локальный офлайн-комплект

Полная приёмка возобновлена по запросу от 27.09.2026. Комплект содержит реализованные функции, исходники и локальные зависимости. Текущее состояние — в PROGRESS.md; принятые решения — в docs/DECISIONS.md.

## Состав

- `documents/user-guide.docx` и `.pdf` — руководство пользователя.
- `documents/administrator-guide.docx` и `.pdf` — обслуживание, параметры, резервирование, восстановление и обновления.
- `documents/technical-description.docx` и `.pdf` — архитектура, API и лицензии.
- `documents/acceptance-status.docx` и `.pdf` — состояние реализации и оставшаяся приёмка.
- `documents/presentation.pptx` и `.pdf` — презентация решения.
- `acceptance/` — итоговый make check, результаты нагрузки, браузеров, восстановления, отказа backend и чистой установки; неуспешные ранние нагрузочные профили сохранены отдельно.
- `offline/source.zip` — исходники и локальные учебные ресурсы; действующие секреты, БД пользователей и записи реальных учебных звонков не включаются.
- `offline/images.tar`, `images.json` — подготовленные Linux-образы Docker и точные идентификаторы.
- `offline/wheels/` — пакеты Python для локальных установочных инструментов (Windows x64 / Python 3.11 для текущего комплекта).
- `offline/manifest.json` — размеры и SHA-256 файлов; `manifest.sha256` — контрольная сумма списка.

Лицензии находятся в `docs/licenses` внутри исходников и в исходных notices образов. Авторские учебные классификатор/улицы/сценарии обозначены как учебные, а не как нормативная база заказчика. Локальная модель имеет собственные условия использования, приведённые в документации.

## Установка без сети

На новом компьютере заранее установите Python 3.11 x64 и Docker Desktop с Linux engine / Docker Compose. Скопируйте весь каталог `offline` с доверенного носителя. Из него выполните команду с **новым, ещё не существующим** каталогом назначения:

```powershell
python install_offline.py --target "C:\Dispatcher112"
```

Установщик проверит контрольные суммы, извлечёт исходники, создаст `.venv`, установит пакеты только из `wheels`, загрузит локальные образы, создаст новые секреты и сертификаты, запустит миграции и учебные данные. Существующие контейнеры или тома проекта dispatcher112 блокируют новую установку: для работающего экземпляра используется штатное обновление. Порты 5173/8000 и медиапорты должны быть свободны. По окончании откройте `https://localhost:5173`; локальный CA подключается по `docs/TLS.md`. Установка не добавляет CA в доверенные сертификаты ОС автоматически. Учебные учётные записи приведены в README.md.

Для независимой установки рядом с существующим проектом задайте отдельные имя, порты и адрес медиапотоков:

```powershell
python install_offline.py --target "C:\Dispatcher112Second" --project dispatcher112_second --ui-port 25173 --api-port 28000 --media-address 127.0.0.3
```

Установщик проверяет занятость TCP/UDP, контейнеров, томов и сетей выбранного проекта. Его база, сертификаты и секреты создаются отдельно. Ключи, использованные при загрузке модели на машине сборки, в исходный архив не включаются.

Дальнейший запуск из каталога проекта:

```powershell
.venv\Scripts\python.exe scripts/compose.py up --detach --no-build --wait
```

Список образов закреплён локально; пересборка в изолированном контуре не требуется. Монитор состояния запускается штатной командой вместе с сервисами. Остановка с сохранением данных: `.venv\Scripts\python.exe scripts/compose.py down`. Для нового выпуска используйте штатное пакетное обновление. Архивы и созданные данные сохраняются при ошибке установщика, автоматического удаления нет. Результат проверки отдельной чистой установки фиксируется в PROGRESS.md.

## Повторная подготовка комплекта

На машине сборки с готовыми образами и ресурсами:

```powershell
python -m pip install -r scripts/requirements-delivery.txt
python scripts/build_delivery_docs.py
python scripts/build_offline_bundle.py
```

При готовых локальных wheels: `--refresh-images` обновляет исходники и образы без загрузки пакетов; `--refresh-source` обновляет только исходники и контрольные суммы.

Только подготовка `wheels` обращается к репозиторию пакетов. В установленной программе и при офлайн-установке сетевые источники пакетов не используются. Контрольные суммы выявляют повреждение; подлинность носителя определяется организацией передачи. Подписанные обновления используют отдельный доверенный ключ издателя.

## Проверенная установка и внешние остатки

27.09.2026 комплект установлен без загрузки пакетов/образов из сети в новый каталог `.offline-acceptance-20260927`, проект `dispatcher_delivery_20260927`, UI 25173/API 28000. Созданы новые секреты, CA, тома и база; исходный проект не изменялся. Готовы 13 сервисов с корнем только для чтения; проверены 513 исходных файлов и точные ID всех образов, доверие CA/имя хоста и реальные PDF/XLSX/CSV/XML. Результаты — `artifacts/ui-review/full-tz-offline-installation.json`; исходный manifest сохранён рядом как `full-tz-installed-manifest.json`.

Общий make check: 1001 серверный, 128 установочных и 69 UI-тестов. В основной установке приняты восстановление/возврат, отказ backend, три браузера, 30 секунд offline и описанный профиль 100 HTTP/WS-пользователей с пятью браузерами. Условия и фактические результаты — PROGRESS.md и CLUSTER.md.

Предметная приёмка требует оригинальных PDF-билетов и классификаторов заказчика; в предоставленной папке их нет. Целевой сервер от 32 ГБ ОЗУ, физические рабочие места/гарнитуры и распределение по разным компьютерам проверяются на оборудовании учебного центра. Загрузка на внешнюю платформу не выполнялась — адрес и доступ не предоставлены.

На чистой установке Chrome прошёл 111 компоновок, полный учебный цикл и восстановление после 30 секунд без сети (`artifacts/ui-review/offline/chrome/responsive.json`). Проверочный экземпляр остановлен, его файлы и тома сохранены. Основной проект оставлен на https://localhost:5173.
