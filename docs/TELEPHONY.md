# Локальная учебная телефония

Этап 13 добавляет Asterisk 22.9.0 (пакет Alpine 3.24) и SIP.js 0.21.2. SIP.js входит в локальную сборку фронтенда. Голос передаётся по WebRTC/DTLS-SRTP с кодеком PCMU; облачные SIP-провайдеры, внешние STUN/TURN и телефонные транки не используются. Справочник приложения связывает учебные номера с подготовленными репликами. Номер 112 в этом справочнике — внутренний учебный абонент.

## Использование

1. Запустить подготовленный проект через `make up`, применить миграции через `make migrate` и открыть `https://localhost:5173`. Первичная подготовка сертификатов описана в README.md и TLS.md.
2. Войти студентом и нажать «Включить гарнитуру». Разрешить использование микрофона. «Проверить звук» устанавливает настоящий SIP-вызов на внутренний эхо-тест 9000: голос возвращается в гарнитуру. Завершить проверочный вызов.
3. Для входящего упражнения преподаватель выбирает «Заполнение карточки» и «Голосовой IP-вызов». Реплики готовятся локально до старта. Если подготовка ещё идёт, запуск вернёт объяснение; повторный запуск не создаёт второе занятие.
4. После выдачи карточки АТС вызывает зарегистрированный телефон студента. Кнопка «Ответить на вызов» принимает звонок. Просмотр карточки до ответа не запускает таймер заполнения. При отказе или разрыве доступно повторное получение обращения; время первого приёма не сбрасывается.
5. Для исходящего доклада открыть телефон карточки и выбрать номер справочника. При включённой гарнитуре используется SIP. При выключенной явно обозначается прежняя аудиосимуляция. Текстовый доклад сохраняется отдельно и остаётся обязательным там, где его требует сценарий.

Эхо-тест не записывается. Учебные входящие и исходящие разговоры записываются в WAV; доступ к записи имеет студент и преподаватель соответствующего занятия. Ссылки на записи проходят авторизацию, файлы не выставлены общедоступным каталогом. Кнопка «Скачать MP3» преобразует запись локальным LAME, показывает ожидание и позволяет повторить запрос при ошибке. Исходный WAV сохраняется; временный MP3 удаляется после скачивания. Проверены права доступа, кодирование и обратное декодирование звука.

## Компоненты и данные

- `telephony`: Asterisk и подготовка русских реплик eSpeak NG/SoX. `sip_worker`: выдача звонков, чтение событий ARI, подготовка абонентов, аудит и серверные отметки времени. Один контроллер обслуживает один учебный SIP-сервер.
- `sip_calls`: состояние запроса, направления INBOUND/OUTBOUND, принадлежность студенту/карточке, отметки ответа и завершения. У студента может быть один активный учебный звонок. Случайный одноразовый идентификатор вызова повторно проверяется по реальному SIP-абоненту и занятию.
- Учётные данные SIP выводятся HMAC из установочного секрета, UUID пользователя и хеша его пароля с отдельным назначением ключа. Изменение пароля меняет SIP-пароль. Заблокированный пользователь исключается из конфигурации; действующий разговор завершается контроллером.
- `data/telephony/accounts.conf` содержит служебные SIP-пароли. Каталог исключён из контроля версий. `speech/` содержит предварительные реплики, `recordings/` — записи. Доступ к каталогу на сервере разрешается только обслуживающей учётной записи.
- ARI доступен только внутри Docker-сети. HTTP-шлюз публикует только SIP WebSocket `/sip`, без ARI. Голосовые UDP-порты: 20000–20199. По умолчанию они привязаны к 127.0.0.1.

Для работы с других компьютеров необходимы HTTPS/WSS, доверенный сертификат учебного центра и адрес сервера в `SIP_MEDIA_ADDRESS`; `SIP_MEDIA_BIND` задаёт интерфейс приёма UDP. Настройка общего TLS-контура относится к этапу 15. Обычный HTTP на удалённом IP не предоставляет браузеру доступ к микрофону.

## Проверка

`python scripts/check_sip.py` проверяет регистрацию, реальный эхо-вызов и измеряет передачу звука. `scripts/sip_media_probe.js` подаёт известные звуковые импульсы в реальный отправитель WebRTC, затем сравнивает исходный и возвращённый сигнал на одной звуковой шкале времени. Это полный проход туда и обратно, включая кодирование, SRTP, Asterisk и буфер воспроизведения; измерение не подменяется сетевым RTT.

Для отдельного класса: `docker compose run --rm checks python -m tests.prepare_sip_acceptance`, затем `python scripts/check_sip_classroom.py`. Подготовка выполняется отдельным установочным сервисом: рабочий API не имеет записи в корень `/data`. Создаются отдельные пользователи и занятие с аудитом, история сохраняется. Двадцать браузерных контекстов распределены по четырём процессам Chromium из-за лимита виртуальных микрофонов одного процесса. Используются синтетические микрофоны, но настоящие SIP-сеансы и передача RTP. Это нагрузочный стенд, а не проверка двадцати физических гарнитур.

Все 20 медиапотоков остаются активными; измерительный захват выполняется по очереди на каждом клиенте. Это исключает дополнительную нагрузку двадцати одновременно работающих Web Audio измерителей на одну машину. Приёмка: 240 из 240 импульсов, максимальный полный проход 86,44 мс; затем 20 входящих вызовов, 20 сохранённых черновиков и 20 записей. Отдельный `scripts/check_sip_outgoing.py` проверяет исходящий доклад, серверную длительность, запись, оценку полноты 100 и пять переходов ДДС на ширинах 360–1920 px. Артефакты: `artifacts/ui-review/sip-classroom.json` и `sip-outgoing.json`.

Предыдущие одновременные измерительные захваты давали до 211,98 мс на одной машине; этот результат сохранён как ограничение методики, а не объявлен успешным. Результат приёмки относится к описанному стенду. На целевом оборудовании тест повторяется. Настройка `jitterBufferTarget=20` применяется только в поддерживающем её браузере; [описание W3C](https://w3c.github.io/webrtc-extensions/).

Актуальные результаты и незакрытые проверки перечисляются в PROGRESS.md. До завершения приёмки этап не считается выполненным.

Источники конфигурации: [официальная документация Asterisk WebRTC](https://docs.asterisk.org/Configuration/WebRTC/Configuring-Asterisk-for-WebRTC-Clients/), [API SIP.js](https://github.com/onsip/SIP.js/tree/0.21.2/docs), [официальный каталог пакетов Alpine 3.24](https://dl-cdn.alpinelinux.org/alpine/v3.24/main/x86_64/).
