## Что строим одной фразой

Локальный веб-тренажёр: обучающийся получает карточки происшествий с регламентным дедлайном 30 секунд, проставляет статусы реагирования, пишет комментарии и докладывает по симулятору телефонии; система детерминированно оценивает действия и формирует отчёт преподавателю.

## Стек

Python 3.11 + FastAPI + SQLAlchemy 2.0 (async) · React 18 + TypeScript + Vite · PostgreSQL 15 · Redis + arq · LanguageTool self-hosted · всё в docker-compose.

## Пять правил, нарушение которых ломает решение

1. **Никакого сетевого доступа в рантайме.** Шрифты, звуки, модели, библиотеки — локально. Контур изолирован, это требование заказчика, а не пожелание.
2. **Работа без GPU обязательна.** Генерация сценариев — до занятия, в фоне. В рантайме занятия модель не вызывается. GPU — опциональный ускоритель за флагом.
3. **Автомат статусов проверяется на сервере.** Фронтенд рисует только то, что пришло в `available_statuses`, но бэкенд валидирует каждый переход независимо.
4. **Время считает сервер.** Клиентские часы не используются в оценке ни при каких условиях.
5. **Оценка детерминирована.** Одинаковые события — одинаковый балл. LLM в оценке не участвует.

## Первая команда

```bash
make up && make migrate && make seed && make demo
```

После неё должна открываться система с готовым занятием, тремя учебными пользователями и набором сценариев.
